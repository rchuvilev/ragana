# ragana

Локальный RAG по папке с документами. Кидаете файлы — получаете ответы
с дословными цитатами и указанием источника. Ничего не уходит с устройства.

Одно ядро, три оболочки: **CLI**, **Android APK**, **Chrome-расширение**.

```sh
npm install
sh tools/setup-model.sh                    # 113 МБ, один раз
node cli.mjs index --dir ~/Документы
node cli.mjs ask   --dir ~/Документы "какая франшиза при ДТП"
```

## Что умеет

| | |
|---|---|
| форматы | текст, Markdown, CSV, HTML, **PDF с текстовым слоем** |
| поиск | смысловой (E5) + лексический (BM25), слияние RRF |
| цитаты | дословные, с файлом и номером страницы |
| обновление | только изменённое: новое, правленое, удалённое, **перемещённое** |
| приватность | полностью офлайн после загрузки модели |

## Замеры на Redmi Note 10 Pro (Snapdragon 732G)

| операция | время |
|---|---|
| загрузка модели | 6.2–6.8 с |
| эмбеддинг одного фрагмента | **205 мс** |
| индексация 3 файлов (18 фрагментов) | 47 с |
| поиск | **311 мс** (из них ~205 мс — эмбеддинг вопроса) |

Качество на размеченном наборе (12 вопросов, 18 фрагментов):

| метод | R@1 | R@3 | MRR |
|---|---|---|---|
| BM25 | 5/12 | 6/12 | 0.48 |
| **E5** | **8/12** | 11/12 | **0.80** |
| гибрид + расширение запроса | 8/12 | 11/12 | 0.78 |

На этом корпусе чистый E5 оказался не хуже гибрида — BM25 здесь слаб.
На другом корпусе соотношение может быть обратным, поэтому режим
выбирается флагом `--mode vector|lexical|hybrid`, а не зашит.

## Устройство

```
core/      ядро на чистом JS — работает в Node, WebView и расширении
node/      адаптеры Node: обход ФС, PDF, эмбеддер
web/       интерфейс (общий для браузера, APK и расширения)
android/   WebView-обёртка + мост к SAF
extension/ манифест MV3 + service worker
```

### Почему не взята готовая векторная БД

Измерено (`node test/bench.mjs`), размерность 384:

| фрагментов | поиск перебором | доля от стоимости запроса |
|---|---|---|
| 1 000 | 1.0 мс | 0.23% |
| 20 000 | 19 мс | 4.2% |
| 50 000 | 47 мс | 9.8% |

Эмбеддинг вопроса стоит 205–438 мс, поэтому индекс вроде HNSW ускорял бы
те несколько процентов, которые и так незаметны. Отвергнуты: Voy (мёртв
с 2023), Orama (2.2 МБ, всё в памяти), wa-sqlite (OPFS недоступен в
расширении — это и решило).

### Почему хэши, а не время изменения

Android SAF сохраняет mtime исходника при копировании, так что
отредактированный файл приезжает со старым временем и не попал бы в
переиндексацию. Хэширование стоит 698 МБ/с — гигабайт документов дешевле
четырёх фрагментов. Побочная выгода: перемещение файла распознаётся и
**не требует повторного эмбеддинга**.

### Почему цитаты не могут быть выдуманы

Модель (когда она есть) возвращает JSON со **ссылками** на фрагменты —
заголовки порождать можно, текст нет. Валидатор отвергает ссылку на
несуществующий фрагмент и выход за границы; при любой ошибке — откат к
обычной выдаче. Галлюцинация в фактах структурно невозможна.

## Сборка оболочек

```sh
sh tools/build-apk.sh         # → ragana.apk (59 КБ)
sh tools/build-extension.sh   # → extension/dist (14.9 МБ)
```

APK собирается **без Gradle**, прямо на телефоне. `aapt2` и `zipalign`
существуют только под x86-64, поэтому идут через `qemu-x86_64`.

## Проверка

```sh
npm run check   # 153 теста + строгая проверка типов
node test/eval.mjs --dir ~/Документы   # замер качества поиска
```

Типы — JSDoc + `tsc --checkJs` со `strict` и `noUncheckedIndexedAccess`.
Без шага сборки: файлы грузятся в WebView и расширении как есть.

## Чего пока нет

- **OCR для сканов и фото.** Распознаётся формат и честно сообщается, что
  нужен OCR, — вместо молчаливой индексации пустого документа.
- **Генерация связного ответа.** Сейчас выдаются цитаты. Структурирование
  через LLM реализовано и покрыто валидатором, но не проверено вживую:
  `minis-model-use` показывает 0 доступных моделей.
- **Модель внутри APK.** Пока тянется с CDN при первом запуске.

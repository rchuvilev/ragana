# Требования

Источник: запрос пользователя от 2026-11-25. Цель — **RAG-инструмент, который
подключается к любой модели в пайплайн**: даём промпт, получаем результат,
добавляем к промпту в контекст и передаём рабочей модели (Claude, Codex,
локальная — безразлично).

## Форма поставки

Единый исполняемый файл через `bun build --compile`.
Проверено на этом устройстве: aarch64/musl, бинарь 75 МБ, аргументы принимает.

Платформа — **десктоп**. APK отложен по решению пользователя.

## Раскладка на диске

Создаётся при первом запуске **рядом с исполняемым файлом**:

```
<каталог бинаря>/
└── ragana/
    ├── ragana-db.sqlite      база RAG (векторы, чанки)
    ├── knowledgebase/        сюда пользователь кладёт документы
    ├── knowledgebase.json    реестр файлов для частичной индексации
    └── searches/             история поисков
```

Правописание: `knowledgebase` — слитно, это устоявшийся термин
(ср. `codebase`). Вариант `knowledge-base` тоже корректен, но слитный
короче и совпадает с именем JSON-файла.

## Флаги

| флаг | действие |
|---|---|
| `--index` | переиндексация папки `knowledgebase` |
| `--search <промпт>` | RAG-поиск |
| `--open` | открыть папку документов в файловом менеджере |
| `--gui` | TUI-режим |

Если флагов несколько — **используется только первый**.
Запуск без флагов (или кликом) = `--gui`.

## Реестр `knowledgebase.json`

```jsonc
{
  "relative/path/file.pdf": "<хэш>"
}
```

Ключ — относительный путь, значение — хэш. При индексации файл
переиндексируется, если:
- ключа нет в реестре (новый файл), **или**
- хэш изменился (файл правлен).

Ключи, исчезнувшие с диска → чанки удаляются из базы.

## Подготовительный этап: расшифровка в MD

Для **всех не-текстовых** файлов рядом создаётся одноимённый `.md`
(обновляется при изменении оригинала). Векторизация и анализ работают
**с этим MD**, а не с оригиналом.

### Координаты в MD обязательны

Без них цитата не указывает, куда смотреть в исходнике.

| тип | координата | инструмент | проверено |
|---|---|---|---|
| PDF с текстовым слоем | **страница** | `pdftotext -layout` (разделитель `\f`) | ✅ 2 страницы, 4151 + 2508 симв. |
| PDF-скан | **страница** | `pdftoppm` → `tesseract` | — |
| изображения, сканы | **страница** (= номер файла/кадра) | `tesseract`, **66 языков** | ✅ «Франшиза составляет 300 евро» символ в символ; рус+англ+нем на одной картинке |
| аудио | **таймкод** `[начало, конец]` | Whisper через Transformers.js | ✅ отдаёт `chunks[].timestamp` |
| видео | **таймкод** | `ffmpeg` (дорожка) → Whisper | — |

Формат заголовка фрагмента в MD: `## [с. N]` или `## [MM:SS–MM:SS]`.

### Замеренная стоимость ASR — причина сделать его опциональным

| модель | загрузка | 3.74 с аудио |
|---|---|---|
| whisper-tiny | 24.3 с | 5.7 с |
| whisper-base | 23.2 с | 16.4 с (**×4.4 реального времени**) |

Час видео ≈ 4.5 часа расшифровки. Поэтому аудио/видео обрабатываются
**по явному согласию**, с предупреждением о времени; по умолчанию `tiny`.
Tesseract для сравнения — доли секунды на страницу.

ASR подключается как заменяемый модуль: при необходимости скорости
ставится `whisper.cpp` (55.5k★) вместо Transformers.js.

## История поисков

При каждом `--search` пишется
`searches/<yyyy-mm-dd---hh-mm-ss---ms>.json`:

```jsonc
{
  "<промпт>": {
    "<путь-к-файлу>": "<результат>"
  }
}
```

Результаты ранжированы и отсортированы. Нужно для истории и анализа.

## TUI (`--gui`)

Кнопки, запускающие **сам бинарь дочерним процессом** с нужным флагом.
Видно прогресс выполнения и оценку оставшегося времени.

Почему дочерним процессом, а не в том же: индексация идёт минутами и
может быть прервана; отдельный процесс даёт честный прогресс, возможность
остановить и изоляцию падения парсера от интерфейса.

## Применение в пайплайне

```sh
ragana --search "условия возврата" --json | <обработка> | claude -p "..."
```

Отсюда требование: `--search` обязан иметь машиночитаемый вывод и
предсказуемый код возврата.

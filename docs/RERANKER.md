# Реранкер: замерен и отклонён

Решение принято по цифрам, а не по соображению «так принято в RAG».

## Что замерено

`Xenova/bge-reranker-base`, квантованный int8, на Snapdragon 732G
(Redmi Note 10 Pro) — то же железо, на котором мерился весь остальной
пайплайн.

| | |
|---|---|
| размер модели | **266 МБ** |
| загрузка | 8.3 с |
| оценка одной пары | **1546 мс** |

Качество при этом нормальное — модель различает релевантность уверенно:

```
 -2.321  Франшиза по каждому страховому случаю составляет 300 евро.
-10.178  Ежегодный отпуск предоставляется по согласованию…
-10.179  Выплата производится в течение десяти рабочих дней.
```

## Почему отклонён

Cross-encoder прогоняет модель на **каждую пару** «запрос + фрагмент».
Отсюда стоимость:

| что | время |
|---|---|
| весь текущий поиск | **0.3 с** |
| переранжировать top-5 | 7.7 с |
| переранжировать top-10 | 15.5 с |
| переранжировать top-20 | **30.9 с** |

Переранжирование двадцати результатов — это **99× от стоимости всего
поиска**. Плюс 266 МБ к бинарю, который и так 520 МБ.

## Чего мы лишаемся

Немногого, и это тоже измерено. Текущие показатели на размеченном
наборе:

| | R@1 | R@3 | MRR |
|---|---|---|---|
| правила + разбиение запроса | 9/11 | **11/11** | 0.89 |

**R@3 = 11/11**: нужный фрагмент всегда в тройке. Реранкер улучшает
именно порядок внутри top-k — то есть ту часть, где уже почти нет ошибок.
Потолок улучшения здесь: перевести 2 из 11 вопросов с позиций 2–3 на
первую. За 31 секунду и 266 МБ.

## Когда вернуться к вопросу

Три условия, при которых расчёт изменится:

1. **Корпус вырастет до тысяч документов.** Тогда R@3 просядет, и
   реранкер получит что улучшать.
2. **Появится железо посильнее.** На настольном процессоре 1546 мс
   превращаются в десятки миллисекунд, и 20 пар укладываются в секунду.
3. **Найдётся лёгкий многоязычный cross-encoder.** `ms-marco-MiniLM-L-6`
   быстрее на порядок, но **только английский** — для русских документов
   бесполезен. Многоязычных мелких моделей на момент проверки нет.

## Что сделано вместо

Дешёвые приёмы, дающие сопоставимый эффект за ~0 мс:

- **разбиение составного вопроса** — каждая часть ищется отдельно,
  результаты сливаются RRF;
- **расширение запроса правилами** — MRR 0.82 → 0.89;
- **слияние RRF** — согласие независимых методов вместо доверия одному.
